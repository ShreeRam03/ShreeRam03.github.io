How my website blocker works, and what I'd fix in it now

During my internship at Supraja Technologies I built a small Windows tool that lets an admin block websites on a machine, and refuses to unblock any site that VirusTotal flags as malicious. It's written in Python with a Tkinter interface. This post explains how it works and what I'd change now that I know more.

The idea

Most people never think about the hosts file, but every Windows machine checks it before asking DNS where a domain lives. If you map a domain to 127.0.0.1, the browser tries to load it from your own computer, finds nothing, and the site is effectively blocked. No extra software or network appliance is needed.

# C:\Windows\System32\drivers\etc\hosts
127.0.0.1   badsite.example
Blocking is easy to do and just as easy to undo. The interesting part is who is allowed to unblock a site, and which sites should never be unblocked.

How it works

01Admin rightsRelaunches itself elevated so it can edit the hosts file.
02Owner checkEmail is matched against a stored SHA-256 hash.
03One-time passwordEmailed to the owner; required for every change.
04VirusTotal gateFlagged sites can't be unblocked, even with the password.
  • Admin rights. The hosts file lives in C:\Windows\System32\drivers\etc\, so the tool checks for admin rights and relaunches itself elevated if it doesn't have them.
  • A registered owner. The owner registers a Gmail address once. The tool stores only a SHA-256 hash of it, not the address itself.
  • A one-time password. Before any block or unblock, the owner enters their email. If its hash matches, the tool emails a fresh 8-character password, and the action only goes through with that password.
  • Blocking appends a 127.0.0.1 domain line to the hosts file.
  • Unblocking first asks the VirusTotal URL report API about the domain. If any engine flags it, the unblock is refused.
def scan_website(website):
    url = "https://www.virustotal.com/vtapi/v2/url/report"
    params = {"apikey": virustotal_api_key, "resource": website}
    response = requests.get(url, params=params)
    if response.status_code == 200:
        return response.json().get("positives", 0) > 0

That last step is the part I'm proudest of. A person can talk themselves into unblocking a site; the tool won't let them if the threat data says it's bad.

Four things I'd fix now

01Unblocking matches too much

The unblock code removes every hosts line that contains the domain text. Unblocking bank.com would also remove a line for mybank.com. The fix is to parse each line and compare the hostname exactly.

02The one-time password uses the wrong random

It's generated with Python's random module, which isn't meant for security. secrets.choice() is the right tool. I'd also add an expiry, so a password sent an hour ago stops working.

03Configuration belongs outside the code

Email sender details and the VirusTotal key should come from environment variables, never the source. The current version on GitHub reads SENDER_EMAIL, SENDER_APP_PASSWORD and VT_API_KEY from the environment.

04VirusTotal v2 is the old API

The tool calls the v2 URL report endpoint. The v3 API returns per-engine verdicts, so I could block on "2 or more engines say malicious" instead of "any single engine", which would cut down false positives.

What I learned

Building the blocking part took an afternoon. Most of the real work, and most of what I'd change, is in the controls around it: who can make a change, how they prove it, and what happens when the data and the human disagree. That's most of security work in general.
